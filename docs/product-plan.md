## 1. 한 줄 정의

**여행이 끝나면, 들른 곳·머문 시간·그날의 날씨와 동승 인원이 정리된 여행 한 편이 차에 남는다. 그 여행은 검색해서 다시 찾고, 휴대폰으로 사진을 붙여 공유하고, 그대로 다시 갈 수 있다.**

## 2. 기능 목록

### 2-1. 자동 기록 (P0)
| 기능 | 규칙 |
|---|---|
| 드라이브 시작·종료 | 기어 P→D/R 시작, P 유지 3분 또는 시동 OFF로 종료. 기어 신호가 없으면 시속 5km 10초 시작, 정지 3분 종료 |
| 이동 묶기 | 드라이브 사이 간격 6시간 미만이면 같은 이동. 닫는 시점: ① HOME 300m 안 도착 ② 집이 아닌 곳에서 6시간 넘게 정차(그 시점에 닫는다) ③ 정차 48시간 초과. ②로 닫은 뒤 그 정차가 숙박(오전 3시 포함)이 되고 48시간 안에 다시 출발하면, HOME이 등록돼 있을 때 닫았던 이동을 다시 열어 이어 붙인다 |
| 판정 3단계 | 닫힌 이동을 셋으로 나눈다. **확실한 일상**: 한쪽 끝이 집, 다른 끝이 회사(각 300m 안)이고 방문지 0개. 또는 들른 방문지가 단골 한 곳뿐. 묻지 않고 일상 이동으로 보관한다. **확실한 여행**: 방문지 2곳 이상, 또는 숙박 1회 이상, 또는 경로 중 가장 먼 점이 집과 회사 양쪽에서 30km 이상. 묻지 않고 여행으로 저장한다. **애매한 이동**: 그 밖(집→집 무정차 드라이브, 단골이 아닌 곳 한 곳 등). 도착 카드에서 묻는다(2-3). 판정은 일상 → 여행 → 애매 순서로 본다 |
| 단골 | 최근 30일 동안 방문지가 된 횟수가 3번 이상인 곳(150m 안). 이번 이동은 세지 않는다 |
| 정차 요약 | 단골·집·회사 추정용. 모든 정차(여행·일상 이동·집 밖 정차 모두)의 좌표(소수 3자리, 약 100m), 도착·출발 시각, 방문지 여부만 30일 보관한다. 경로·장소 이름·메모는 넣지 않는다. 일상 이동을 7일 뒤 지워도 정차 요약은 남는다 |
| 일상 이동 | 확실한 일상과, 질문에 답하지 않은 애매한 이동. 목록에는 보이지 않고 7일 뒤 자동으로 지운다. 그 안에 "여행으로 남기기"로 옮길 수 있다 |
| 집·회사 위치 | 칸마다 내비 즐겨찾기 HOME/OFFICE를 먼저 쓴다. 없으면 설정에서 직접 정한 위치(설정의 "지금 위치로 정하기"), 그것도 없으면 추정한다. 집: 최근 7일 중 4일 이상 오전 3시에 서 있던 곳(150m 안). 회사: 최근 14일 중 평일 6일 이상 09~18시에 4시간 넘게 서 있던 곳. 추정 조건을 채우는 곳이 없으면 없음. 설정에 "집으로 쓰는 위치", "회사로 쓰는 위치"와 출처(내비 등록 / 직접 정함 / 추정)를 보여 주고 바꿀 수 있다. 직접 정한 위치는 "추정으로 되돌리기"로 되돌린다 |
| 방문지 판정 | P단 + 도어 열림 + 10분 이상 체류. 같은 장소 150m 안 재정차는 하나로 합침. 수치는 단위 테스트로 고정 |
| 장소 이름 | ① 내비 목적지로 도착했으면 `getDestinationInfo` 이름 ② 아니면 카카오 로컬 API로 좌표 주변 POI 이름. 반경 150m 안에 관광명소가 있으면 거리와 관계없이 그중 가장 가까운 곳, 없으면 관광명소·문화시설·숙박·음식점·카페 중 가장 가까운 곳. 이름 끝의 시설 이름(주차장, 인증센터, 캠핑장, 입구 등)은 남은 말이 장소 이름(해변, 해수욕장, 공원, 시장, 역 등)으로 끝날 때만 뗀다(2026-11-15) ③ 실패 시 행정동(카카오 로컬 좌표→행정구역) ④ 오프라인이면 "방문지 n"으로 저장하고 다음 온라인 때 채움 |
| 경로 | FusedLocation 1초 표본, 저장은 20m 간격으로 줄임. 지원 안 하면 NaviHelper `getCurrentLocationInfo` 10초 폴링 |
| 차량 이벤트 | 와이퍼 ON 구간 → 비, 좌석 탑승 → 동승 인원, 외기온(AAOS, 지원 시). 방문지 카드에 붙임 |
| 휴게소·주유 구분 | 체류 10분 미만 P 정차는 "잠깐 정차"로 따로 저장(방문지 아님). 다시 갈 때 휴게소 경유 제안 근거 |

### 2-2. 주행 중 화면 (P0)
- 표시: "기록 중 · 3시간 10분" 한 줄 + 숫자 2개(이번 여행 거리, 방문지 수). 지도·목록·버튼 없음. 주행 중에는 출퇴근인지 여행인지 알 수 없으므로 "여행"이라고 쓰지 않는다.
- 주행 중 터치는 받지 않는다. 목록·상세·공유·다시 가기를 보던 중이었으면 "차를 세우면 보던 화면으로 돌아가요"를 띄운다.

### 2-3. 도착 카드 (P0)
- 방문지에서 P단 + 도어 열림 시: 화면 변화 없음(내리는 중).
- 확실한 여행이 닫혔을 때(P단): 여행 요약 카드 1장. 방문지 수("3곳을 다녀왔어요"), 달린 거리, 여행 시간, 함께 탄 사람, 가장 오래 머문 곳, 비 온 구간. TTS 한 문장("세 곳 다녀온 여행을 저장했어요.")은 설정에서 끌 수 있다.
- 애매한 이동이 닫혔을 때: 같은 요약 카드에 "이번 이동도 여행으로 남길까요?"와 [지우기] [남기기]. 음성은 내지 않는다. [남기기]는 여행으로 저장, [지우기]는 바로 영구 삭제(7일 보관 없음). 답하지 않고 닫거나 10분이 지나거나 출발하면 일상 이동으로 보관. 답을 받기 전에는 목록에 넣지 않는다.
- 확실한 일상이 닫혔을 때: 카드를 띄우지 않는다.
- 집이 아닌 곳에서 6시간 정차로 닫힌 이동: 다음 시동 때 정차 상태에서 카드를 띄운다. 확실한 여행이면 제목 위에 "지난 여행을 저장했어요", 애매한 이동이면 위의 질문 카드.

### 2-4. 여행 목록·상세 (P0)
- 목록: 최신순 카드. 카드 = 날짜, 제목(첫 방문지 → 마지막 방문지, 예 "경포해변 → 강릉중앙시장"), 방문지 수, 동승 인원, 비 아이콘.
- 상세: 왼쪽 경로 그림(지도 타일 없이 경로 선 + 방문지 번호 점, 5절 결정), 오른쪽 방문지 타임라인(도착-출발 시각, 체류 분, 비, 메모). portrait(841px)에서는 타임라인만.
- 여행 제목·방문지 이름은 정차 중 수정 가능. 방문지 삭제·여행 삭제·전체 삭제.
- 일상 이동: 목록 맨 아래 "일상 이동 n건 · 7일 뒤 자동으로 지워요" 줄 → 일상 이동 화면. 항목마다 날짜·시각·거리와 [여행으로 남기기]. 일상 이동은 검색·1년 전 이맘때·공유·다시 가기 대상이 아니다.

### 2-7. 공유와 사진 (P1)
서버를 두지 않는다. 사진은 휴대폰에서만 붙이고, 사용자가 공유 이미지를 직접 보내기 전에는 어디에도 올라가지 않는다.
1. 여행 상세에서 "휴대폰으로 보내기" → 차 화면에 QR 1개.
2. QR URL의 `#` 뒤에 여행 데이터를 압축해 넣는다: 방문지 이름·좌표(소수 4자리)·도착/출발 시각·비 여부, 경로는 단순화한 점 목록. 상한 1KB. 서버는 데이터를 받지 않는다(`#` 뒤는 브라우저가 전송하지 않음).
3. 휴대폰 웹 페이지(정적 파일)가 여행을 그린다: 방문지 타임라인, 방문지별 카카오맵·네이버지도 링크.
4. **사진 붙이기**: 휴대폰 페이지에서 갤러리 사진을 고르면, 페이지 JS가 EXIF 촬영 시각(`DateTimeOriginal`)을 읽어 방문지 도착-출발 시간 안에 드는 사진을 그 방문지에 붙인다. 구간 밖 사진은 "이동 중" 묶음. 처리는 휴대폰 브라우저 안에서만 한다.
5. 공유 이미지를 만들어 저장하거나 카카오톡·인스타그램으로 보낸다. 이미지는 4종이다.
   - 스토리(1080×1920): 배경 없는 경로 선 + 방문지 번호 점, 아래에 날짜·여행 제목과 숫자 3개(총 거리, 방문지 수, 여행 시간).
   - 사진 배경(1080×1920): 사용자가 고른 사진 1장을 배경으로 깔고 그 위에 경로 선과 숫자 3개를 겹친다.
   - 정사각형(1080×1080): 스토리와 같은 구성을 정사각형에 넣는다(카카오톡·인스타그램 게시물용).
   - 들른 곳별(1080×1350): 방문지·숙박마다 대표 사진 + 번호 + 이름 + 시각·머문 시간을 세로로 쌓는다. 한 장에 3곳까지 넣고, 4곳부터는 여러 장으로 나눈다(인스타그램 캐러셀용).
   - 경로 선은 휴대폰 페이지가 hash의 점 목록으로 canvas에 직접 그린다. 지도 타일은 쓰지 않는다.
6. 위치 가리기: 공유 데이터에서 HOME·OFFICE 500m 안의 경로 점과 방문지를 뺀다. 방문지별 공유 제외 선택.

확인할 것
- iOS Safari가 업로드 시 EXIF 위치를 지우는 경우가 있다. 이 앱은 촬영 시각만 쓰므로 영향을 받지 않는지 실기기로 확인한다.

- 첫 실행 때 위치 기록 동의. 언제든 기록 끄기.
- 여행 1건 삭제, 전체 삭제.
- 출퇴근 같은 일상 이동은 7일만 보관하고 자동으로 지운다. 단골·집·회사 추정은 기기 안의 정차 요약(좌표 약 100m 단위, 시각, 방문지 여부)으로만 계산하고, 정차 요약은 30일 뒤 지운다. 전체 삭제는 정차 요약도 지운다.
- 추정한 집·회사 위치는 설정에서 보이고 바꿀 수 있다. 첫 실행 동의 화면에서 내비에 집·회사를 등록하면 더 정확하다고 안내한다.
- 공유 데이터는 2-7의 위치 가리기 규칙을 적용하고, 공유 전에 화면에 "보내는 것: 방문지 3곳, 경로 / 보내지 않는 것: 집·회사 근처, 사진"을 표시한다.
- App Market 등록용 이용약관·개인정보처리방침 URL을 만든다(위치 앱 필수).

## 4. 완성도 기준 (수치 목표)

| 항목 | 목표 |
|---|---|
| 도메인 자동 시험 | 도메인 150개 이상 + 골든 시나리오 9개 |
| 시연 데이터 | 여행 시나리오 9개(아래). 경로는 주요 지점을 직선으로 이은 근사 경로(실제 도로 형상으로 교체 예정), 1·10·60배속. 시연 여행 넣기에 일상 이동 2건 포함 |
| 실제 SDK 연결 | Vehicle·NaviHelper·FusedLocation·TTS·STT 5개 모두 에뮬레이터에서 실제 호출 확인 기록 |
| 내비 연동 | `requestRoute` + `requestRouteWithWaypoints` 구간 이어 붙이기 확인 |
| 주행 중 제한 | 주행 중 터치 전면 차단 + `CarUxRestrictionsManager` 제한 준수 + 제한 상태 시연 토글 |
| 공유 | 서버 없음 + 인코더·디코더 왕복 시험 + EXIF 배치 시험 |

골든 시나리오 9개 (시나리오 재생기 + 기대 결과를 테스트로 고정)
1. 강릉 당일: 방문지 3곳, 카페 구간 비, 3명.
2. 제주 2박 3일: 드라이브 9개를 여행 1개로 묶음, 숙소는 방문지가 아니라 "숙박"(체류 6시간 이상 + 야간).
3. 출퇴근 5일: 여행 0개, 일상 이동 10건, 질문 0번.
4. 장거리 귀성: 휴게소 2회(체류 15분, 8분) → 방문지 1개 + 잠깐 정차 1개.
5. 같은 장소 재정차: 주차장 이동으로 120m 옮겨 다시 P → 방문지 1개.
6. 위치 신호 끊김: 터널 3km 구간 표본 없음 → 경로 연결, 방문지 판정 영향 없음.
7. 집→집 해안도로 드라이브: 방문지 0개, 가장 먼 점 30km 미만 → 애매한 이동, 질문 카드 1번.
8. 퇴근길 단골 마트: 최근 30일 마트 방문 3번 이력 + 회사→마트 20분→집 → 일상 이동, 질문 0번.
9. 부모님 댁 편도, 1박 뒤 귀가: 집→부모님 댁(120km) 도착 6시간 뒤 닫힘 → 오전 3시 지나 숙박 → 다음 날 귀가 때 다시 열어 여행 1건.
