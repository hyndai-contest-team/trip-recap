# 1부 — Virtual Console 로 실제 신호 넣기

환경: Pleos Connect Emulator v2.1.0 (AVD `pleos_connect`, cold boot), debug 빌드, 앱은 차량 모드(`mode vehicle`).

## Virtual Console 이 받는 요청
Virtual Console 은 에뮬레이터가 8088 포트로 여는 웹 페이지다(`adb forward tcp:8088 tcp:8088` 뒤 `http://127.0.0.1:8088/`). 페이지의 JavaScript 와 `/vehicle/catalog` 응답에서 읽은 요청 형식이고, Pleos 문서에는 없다. 에뮬레이터 버전이 바뀌면 달라질 수 있다.

| 신호 | 요청 |
|---|---|
| 현재 값 | `GET /vehicle/state` |
| 기어 | `PUT /vehicle/gear?gear=Park\|Reverse\|Neutral\|Drive` |
| 속도 | `PUT /vehicle/controls?speed=<km/h>&accelerator=<%>&brake=<%>` |
| 도어 | `PUT /vehicle/body?door_fl\|door_fr\|door_rl\|door_rr=true\|false` |
| 좌석 | `PUT /vehicle/seat?kind=occupied&value=true\|false&area=driver\|passenger\|rear_left\|rear_right` |
| 와이퍼 | `PUT /vehicle/body?front_wiper=Off\|Auto\|Low\|High` |
| 세션 | `POST /browser/session?client=<이름>` |

- 값을 바꾸는 요청은 직전 3초 안에 세션 요청이 있어야 받아들여진다. 없으면 `503 {"error":"emulator_inactive"}` 가 온다. 세션이 끊겨도 넣어 둔 값은 남는다.
- 위치는 Virtual Console 에 없다. `adb emu geo fix <경도> <위도>` 로 넣으면 FusedLocation 이 그 좌표를 준다.
- 이 요청들을 `tools/vconsole.sh` 로 묶었다.

## 앱이 받은 신호
| 넣은 값 | 앱에서 본 것 |
|---|---|
| 기어 D | SDK 로그 `VENDOR_GEAR_SELECTION value = 8`, CarDrivingState 0→1, 주행 중 화면("여행 기록 중 · 0분")으로 바뀜 |
| 속도 30km/h | 앱을 다시 시작했을 때 첫 값 `speed(m/s)=8.333334`, CarDrivingState 1→2, `uxRestricted=true` |
| 기어 P | `VENDOR_GEAR_SELECTION value = 4`, 목록 화면으로 돌아옴 |
| 운전석 도어 열림·닫힘 | `DOOR_POS areaId = 1 value = 1` → `value = 0` |
| 위치 | 첫 값 `fused location 37.7637,128.899` |

와이퍼, 좌석 값 변화는 요청이 200 으로 끝난 것만 확인했다. 앱 화면에서 비 표시나 인원 변화로 확인하지는 않았다. `IGNITION_STATE` 는 이 에뮬레이터에서 등록되지 않는다(`registerCallback IGNITION_STATE not registered`).

## 방문지 1개 만들기 (`tools/vconsole.sh visit 11`)
순서: 강릉역 근처에서 60초 주행 → P, 운전석 도어 열고 닫기, 11분 대기 → 60초 주행 → P 4분.

결과(`docs/screenshots/vc-1-list.png`, `vc-2-detail.png`): 목록에 여행 1건("방문 1곳 · 4명 · 6.9km"), 상세에 방문지 1(21:56 – 22:24, 28분)과 경로 선.

이 결과에는 실행 두 번이 합쳐져 있다.
- 1회차(21:55 시작)는 4단계 대기 중 22:10 에 에뮬레이터가 닫혀 끝나지 않았다. Android Studio 가 같은 AVD 를 새로 띄우면서 먼저 떠 있던 에뮬레이터가 종료됐다. 재부팅 직후 목록은 비어 있었다.
- 2회차(22:11 시작)는 끝까지 실행됐다. 같은 좌표에 다시 정차했고, 앱이 1회차의 주행 구간(1.1km)과 정차 시작 시각(21:56)을 이어 붙였다. 그래서 체류가 11분이 아니라 28분, 거리가 5.9km 가 아니라 6.9km 로 나왔다.
- 따라서 "도어 열림 + 10분 이상 → 방문지" 가 실제 신호로 동작한 것, 프로세스가 종료된 뒤에도 진행 중이던 기록이 이어진 것은 확인됐다. 한 번의 실행만으로 체류 11분이 표시되는 것은 따로 확인하지 않았다.

## 관찰
- 주행 중에 위치를 캘리포니아(에뮬레이터 기본 좌표)에서 강릉으로 한 번에 옮기면 달린 거리가 8735km 가 된다. 앱은 두 위치 사이 거리를 속도와 비교해 거르지 않는다. `visit` 은 출발 전에 위치를 먼저 옮긴다.
- 그때 주행 중 화면의 "8735km" 는 오른쪽 끝 글자 일부가 잘려 보였다.
- 장소 이름은 카카오 키가 없어 "방문지 1" 로 남았다.

### 확인 중 발견한 것 (고치지 않음)
- 숙박만 있고 방문지가 없는 여행(시나리오 9 끝까지 재생)은 제목이 "드라이브", 숫자 칸이 "0곳 방문"이다. 숙박 이름("부모님 댁")을 제목으로 쓰는 편이 맞다. `Trip.autoTitle` 이 방문지만 본다.
- 시나리오 9를 숙박 전에 끝내면 부모님 댁 정차가 6시간 닫힘 시각에 끝난 방문지로 남는다(카드의 여행 시간 8시간 10분). 기획대로의 동작이다.
- 질문 카드의 숫자 칸 라벨은 "여행 시간"이다. 아직 여행으로 남기지 않은 이동이므로 "이동 시간"이 더 맞을 수 있다.
- 시나리오 9 재생 중 앱 화면이 일상 이동 화면에서 여행 상세로 바뀐 것을 한 번 캡처했다. 이 시간에 보낸 조작 명령은 없었고, 도착 카드의 [여행 보기]가 눌린 것으로 보인다. 에뮬레이터를 직접 조작한 입력인지 앱 동작인지 가리지 못했다.

### 확인하지 못한 것
- 확인 도중 에뮬레이터 연결이 끊겨(`adb: no devices`) 아래는 보지 못했다: 시연 여행 넣기 뒤 목록과 일상 이동 2건, 설정의 "집과 회사" 카드, 동의 화면의 집·회사 등록 안내, 질문 카드를 닫았을 때 일상 이동으로 가는 것.
- 기기에서 DB version 2 → 3 옮기기. 설치 전 기기에 DB 가 없었다. Robolectric 테스트(`TripDatabaseMigrationTest`)로만 확인했다.
- 실제 차량 신호의 시동 켜짐(`IGNITION_STATE`) 수신. 시나리오의 `ignition` 명령으로만 확인했다.
- 집·회사 추정은 단위 테스트로만 확인했다(시나리오 모드에서는 추정을 끈다).
